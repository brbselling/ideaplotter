### Findings

#### F1. `.nojekyll`: an empty file that looks like a stray but is load-bearing

- Source path: `.nojekyll` (0 bytes).
- Proposed target: DO NOT MOVE. Keep in place.
- Reason: a naive sweep could flag it as an empty stray file. It is the marker that turns off Jekyll
  processing on GitHub Pages so the static `index.html` site serves as-is.
- Who loads it: the GitHub Pages build pipeline; nothing in tracked source references it.
- Risk: deleting it lets Jekyll processing run on the site, which can break serving. Zero benefit to
  removing it.

#### F2. No stale docs

README.md says "Current build: `full-bf16`, 136053 games, built 2026-10-27 15:37 CET." `meta.json`
agrees exactly: `"title": "Steam IdeaPlotter (full-bf16)"`, `"n": 136053`, `"built": "2026-10-27
15:37 CET"`. The README data section (Fronkon Games dataset, commit `6a31fcb`, MIT licence) matches
the provenance recorded in the grokbo-computer compare report. `index.html`'s comment naming the
five data files matches the files on disk, and the blueprint confirms the `make_map.py` pipeline is
external and not missing from this repo. No doc action proposed.

#### F3. `meta.json` has three empty cluster labels (observation only)

`meta.json` `clusters` keys `40`, `42`, and `44` are empty strings. The UI falls back to showing just
the cluster number on a game card, so nothing crashes. This is a data-quality nit inside the current
published build, not a folder-sweep item and not stale doc text. Flagged for the owner's decision;
no action proposed here because a fix lands inside `meta.json`, which is regenerated by the external
pipeline on the next build.
